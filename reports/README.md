# Skydio careers — formatting audit

This folder contains a generated report on the formatting consistency of every
job posting on [skydio.com/careers](https://www.skydio.com/careers).

- **[`skydio-job-formatting-report.md`](./skydio-job-formatting-report.md)** —
  the shareable report.
- The report is regenerated by `scripts/analyze_skydio_jobs.py` (live-pulls
  the Skydio Ashby job board API, isolates pre-compensation content, and
  flags formatting drift).

## Scope

Only the **pre-compensation** body content of each posting is analyzed —
i.e. everything from the standard intro paragraph up to (but not including)
either:

1. The `Compensation:` paragraph, or
2. The "At Skydio, our compensation packages…" boilerplate paragraph (the
   form Skydio uses when there's no bold "Compensation:" prefix), or
3. For postings without a compensation block at all (some interns and
   non-US roles), the trailing EEO / "At Skydio we believe that diversity
   drives innovation…" boilerplate.

## How it works

Skydio's careers page is a single HTML/CSS template — body type, size, weight,
line-height, and color are all set globally by Skydio's site CSS. So the only
places real visual inconsistencies can creep in are the **HTML structure** of
each posting (which tags writers use) and any inline `style=""` overrides.

The analyzer parses every posting's HTML and detects:

- Section-label style: `<p><strong>` (the convention) vs. `<h1>`/`<h2>`/`<h3>`
  (which inherit the page's display-heading CSS and render much larger).
- Label casing — Title Case vs. Sentence case vs. ALL CAPS.
- Label punctuation — trailing colon vs. no colon.
- List item structure — `<li><p>…</p></li>` (paragraph-spaced) vs. bare
  `<li>` (visibly tighter line-spacing).
- Inline style overrides other than Ashby's default `min-height:1.5em`
  (`color`, `font-size`, `font-family`, `text-align`, `<font>`, etc.).
- Underline / italic / `<font>` tag usage.
- Empty paragraphs, stray `<br>` tags, non-breaking spaces, double spaces,
  trailing whitespace.
- Whether the posting starts with the canonical "Skydio is the leading…"
  intro paragraph.

It then computes the dominant pattern across the corpus and flags every
posting that drifts from it.

## Re-running the audit

```bash
pip install beautifulsoup4 lxml
python3 scripts/analyze_skydio_jobs.py            # uses cached data/skydio_jobs.json
python3 scripts/analyze_skydio_jobs.py --refresh  # re-pulls live from Ashby API
```
